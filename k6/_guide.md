# k6

## Типы тестов

| Тип теста       | Описание                                                                                             | Визуализация              |
|-----------------|------------------------------------------------------------------------------------------------------|---------------------------|
| Дымовое         | Проверка работоспособности вашего скрипта и адекватной производительности системы при минимальной нагрузке. | Дымовой тест              |
| Средняя нагрузка| Оценка производительности системы в ожидаемых нормальных условиях.                                   | Тест средней нагрузки     |
| Стресс          | Оценка производительности системы на её пределах, когда нагрузка превышает ожидаемое среднее значение.| Стресс-тест               |
| Тест на выносливость (Soak) | Оценка надежности и производительности системы в течение длительных периодов времени.               | Тест на выносливость      |
| Пиковая нагрузка (Spike)   | Проверка поведения и живучести вашей системы в случаях внезапного, короткого и массового увеличения активности. | Спайк-тест (Пиковая нагрузка) |
| Точка сбоя (Breakpoint)    | Постепенное увеличение нагрузки для определения пределов производительности системы.                | Тест точки сбоя           |

## Количество пользователей (VU)

VU ≠ реальные пользователи напрямую. Один VU в k6 — это один **постоянно активный** пользователь.

**Откуда брать цифры:**
- Аналитика/метрики продакшена: пиковый RPS × среднее время запроса
- Нет данных → придумай реалистичный сценарий ("ожидаем 100 одновременных пользователей")

**Формула:** если хочешь X запросов в секунду, и каждая итерация занимает ~2 сек (запрос + sleep), то нужно примерно **X × 2 VU**.

## Длительность

| Тип теста  | Длительность       |
|------------|--------------------|
| Smoke      | 1–5 мин            |
| Average    | 5–60 мин           |
| Stress     | 5–30 мин           |
| Soak       | 2–24 часа (!)      |
| Spike      | 2–10 мин           |
| Breakpoint | До точки отказа    |

**Главный принцип:** длительность должна быть достаточной, чтобы система вышла на стабильный режим. Слишком короткий тест — видишь только ramp-up, а не реальное поведение под нагрузкой.
